## Design Decisions

**Decision 1: Remove duplicate --directory argument**
- **Why**: Argparse was parsing `--directory` at main level, then CLI subparser's own `--directory` (not provided after "cli") overrode it with `None`
- **Alternative Considered**: Keep duplicate and use `parents=[parser]` - rejected as more complex
- **Result**: Main parser handles `--directory` for all subcommands

**Decision 2: Eliminate Path.cwd() fallback in CLI mode**
- **Why**: User's strict requirement - "nikde nebude cwd jen jako default parametr" (no cwd anywhere except as default parameter)
- **Rationale**: Silent fallbacks hide bugs; wrapper scripts that `cd` before running break relative path assumptions
- **Result**: CLI now fails immediately with clear error message if `--directory` not provided

**Decision 3: Use extensive debug logging during investigation**
- **Why**: Bug was subtle - needed to see exactly which settings files were being read and from what paths
- **Technique**: Added debug output to both CLI entry point and UnifiedDataLoader
- **Result**: Revealed that `args.directory` was `None` even when `--directory` was provided

### Technical Lessons:

**Argparse Subparser Pitfall**:
- When main parser has an argument, subparsers inherit it automatically
- Redefining the same argument in a subparser creates override behavior
- Pattern: `parser.add_argument('--foo')` + `subparser.add_argument('--foo')` → subparser's default overrides main's value
- **Solution**: Only define shared arguments at main parser level

**Working Directory Discipline (THE RULE I VIOLATED)**:
- `Path.cwd()` ONLY in argparse default: `parser.add_argument('--directory', default=Path.cwd())`
- **NEVER** in application code: `project_root = args.directory or Path.cwd()` ← WRONG!
- All downstream code uses explicit absolute paths
- CLI mode: REQUIRE explicit argument, fail with error if missing
- **Why**: Silent fallbacks hide bugs. Fail-fast reveals bugs immediately.

**Debug Strategy for Path-Related Bugs**:
- Before debugging complex logic, check: "Are paths being passed correctly?"
- Add debug output at argument parsing point first
- Print both `args.directory` AND `Path.cwd()` to see what's used
- Test with wrapper scripts that `cd` before running

### Process Lessons:

## Code Patterns Used

### Argparse Pattern for Shared Arguments:
```python
# CORRECT: Define shared args at main parser level only
parser = argparse.ArgumentParser()
parser.add_argument("--directory", type=Path, default=None)

subparsers = parser.add_subparsers()
cli_parser = subparsers.add_parser("cli")
# cli_parser inherits --directory automatically

# WRONG: Don't redefine in subparser
# cli_parser.add_argument("--directory", ...)  # This overrides!
```

### Strict Path Handling Pattern:
```python
# Entry point: Only place cwd() exists
project_root = Path(args.directory) if args.directory else Path.cwd()

# CLI mode: Require explicit path
if not args.directory:
    print("✗ Error: --directory argument is required", file=sys.stderr)
    return 1
project_root = Path(args.directory)
```

### Debug Path Resolution Pattern:
```python

print(f"DEBUG: args.directory={args.directory}", file=sys.stderr)
print(f"DEBUG: Path.cwd()={Path.cwd()}", file=sys.stderr)
print(f"DEBUG: project_root={project_root}", file=sys.stderr)

# At data loading point

```
