## Design Decisions

### Thin Wrapper Architecture
- **Decision**: CLI as thin wrapper over existing TUI services
- **Why**: Avoids code duplication, reuses MarketplaceLoader/PluginLoader business logic
- **Result**: Clean separation, no new service layer needed

### Explicit Scope Requirement
- **Decision**: Require `-s/--scope` flag for enable/disable (not optional)
- **Why**: Avoids ambiguity about which settings file to modify
- **Result**: Clear, explicit behavior matching original problem statement

### Plain Text as Default, JSON Optional
- **Decision**: Default to human-readable output, `--json` for scripts
- **Why**: CLI primarily for human use, JSON for automation
- **Result**: Better UX for interactive use

### Scope Status Display Format
- **Decision**: `[I:u E:up D:l]` format for showing plugin status across scopes
- **Why**: Compact representation of 3-scope state in limited space
- **Result**: Consistent with TUI marketplace view

### TDD Throughout
- **Decision**: Write failing tests first for every feature
- **Why**: Plan required TDD, ensures test coverage
- **Result**: 9/9 tests passing, no untested code paths (after fixes)

## Lessons Learned

### Technical Lessons:

1. **Argparse Subparser Architecture**
   - Global flags must go on parent parser (before subcommand)
   - Subcommand-specific flags go on child parser
   - Result: `lazyclaude cli --json list` (not `lazyclaude cli list --json`)

2. **PyFakeFS Testing Pattern**
   - Use `fs.create_file()` for JSON content
   - Use `fake_home` fixture from conftest.py
   - Path resolution: `fake_home / ".claude"` for user config

3. **Type Hints for Collections**
   - Always specify generic type: `list[MarketplacePlugin]` not just `list`
   - Mypy catches these with strict mode enabled
   - Import the type even if only used in hints

4. **Subagent-Driven Development Workflow**
   - Implementer → Spec Reviewer → Code Quality Reviewer → Fix Loop
   - Each stage catches different issue types (missing features vs code quality)
   - Works very well for TDD implementation

### Process Lessons:

1. **Code Review Catches What Tests Miss**
   - Tests passed but type hints were weak
   - Tests covered 40% of filters initially
   - Code reviewer provides independent verification

2. **Two-Stage Review is Powerful**
   - Spec compliance first (did they build what was asked?)
   - Code quality second (is it well-built?)
   - Prevents arguing about quality of wrong implementation

3. **Git Branch Context is Critical**
   - Always verify branch type before suggesting merge/cleanup
   - Long-term feature branches ≠ disposable task branches
   - Ask user about branch strategy if unclear

## Code Patterns Used

### CLI Dispatch Pattern
```python
command_map = {
    "list": handle_list,
    "enable": handle_enable,
    "disable": handle_disable,
}
handler = command_map.get(args.cli_command)
if not handler:
    print(f"Unknown command: {args.cli_command}", file=sys.stderr)
    return 2
return handler(args)
```

### Settings File Manipulation Pattern
```python
# Load or create settings
if settings_path.exists():
    settings = json_module.loads(settings_path.read_text())
else:
    settings = {}

# Update specific section
if "enabledPlugins" not in settings:
    settings["enabledPlugins"] = {}
settings["enabledPlugins"][plugin_id] = enabled

# Write back with formatting
settings_path.write_text(
    json_module.dumps(settings, indent=2) + "\n"
)
```

### PyFakeFS Testing Pattern
```python
def test_feature(self, capsys, fake_home: Path, fs) -> None:
    """Test description."""
    # Arrange
    plugins_dir = fake_home / ".claude" / "plugins"
    fs.create_dir(plugins_dir)
    fs.create_file(
        plugins_dir / "file.json",
        contents='{"key": "value"}',
    )

    # Act
    with patch("sys.argv", ["cli", "command"]):
        with pytest.raises(SystemExit) as exc_info:
            from module import main
            main()

    # Assert
    assert exc_info.value.code == 0
    captured = capsys.readouterr()
    assert "expected" in captured.out
```
