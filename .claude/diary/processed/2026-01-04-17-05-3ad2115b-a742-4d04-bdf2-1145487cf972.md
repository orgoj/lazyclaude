## Design Decisions

### Decision 1: Single Source of Truth for Path Resolution
**Why**: User correctly identified that using `Path.cwd()` in multiple places creates bugs when wrapper scripts change directory. Now cwd is used ONCE at application entry point, then absolute paths are passed everywhere.

**Implementation**:
```python
# In __main__.py - ONLY place cwd is used
project_root = args.directory if args.directory else Path.cwd()
project_config_path = project_root / ".claude"
```

### Decision 2: Include `override_enabled` in is_enabled Calculation
**Why**: Plugins enabled via project/local scope overrides (settings.json `enabledPlugins: {"plugin": true}`) weren't being counted as "enabled". The status `override_enabled` means "not installed here but has enable override" which should count.

**Implementation**:
```python
is_enabled = any(
    status in ("enabled", "override_enabled")
    for status in scope_status.values()
)
```

### Decision 3: Omit Empty Scope Sections in Display
**Why**: Showing `[I: E: D:]` for uninstalled plugins is confusing and wastes space. Only show sections that have values: `[I:u]`, `[I:u E:p]`, etc.

## Lessons Learned

### Technical Lessons:

1. **`MarketplaceLoader` is used by both CLI and TUI** - but they may apply different filters
2. **Plugin scope status types**: `"enabled"`, `"disabled"`, `"override_enabled"`, `"override_disabled"`, `"not_installed"`
3. **Override status matters**: Project/local settings.json can enable/disable plugins even when not installed in that scope
4. **Path.cwd() is dangerous in tools**: Wrapper scripts that `cd` before running will break relative path assumptions

### Process Lessons:

1. **ALWAYS test both CLI and TUI** after making changes to shared infrastructure
2. **Search for existing implementations** before creating new logic - the TUI may already have this solved
3. **Verify outputs match** when two interfaces claim to use the same underlying system
4. **Single source of truth principle**: If CLI and TUI need same data, there should be ONE function that both call

### To Remember for CLAUDE.md:

- **Working Directory Discipline**: `Path.cwd()` should ONLY be used at application entry point to resolve `--directory` argument. All downstream code must use absolute paths.
- **Scope Status Display**: Only show scope sections that have values (`[I:u E:p]` not `[I:u E:p D:l]` when D is empty)
- **Override Status**: Plugins with `override_enabled` in any scope should count as enabled for CLI/TUI display
- **Test Cross-Interface**: Any change to plugin loading affects both CLI and TUI - verify both work identically

## Code Patterns Used

### Scope Status Formatting:
```python
def format_scope_status(scope_status: dict[str, str]) -> str:
    parts = []
    if installed:
        parts.append(f"I:{installed}")
    if enabled:
        parts.append(f"E:{enabled}")
    if disabled:
        parts.append(f"D:{disabled}")
    return f"[{' '.join(parts)}]"
```
